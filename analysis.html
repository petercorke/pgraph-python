Graph analysis

Graph.edges()[source]

Return a set of all edges in graph (base class method)

Returns:

All edges in the graph

Return type:

list of Edge references

The edges are in the order they were added to the graph. This is a new list, so it can be modified or sorted without affecting the graph, and edges can be removed from the graph while iterating over it.

We can iterate over all edges in the graph by:

for e in g.edges():
    print(e)

and select one by index, for example the second edge added is g.edges()[1].

Note

Like Vertex.edges() this is a list, but where that lists the edges attached to one vertex, this lists every edge in the graph once. A self-loop is one edge here, but appears twice in the Vertex.edges() of an undirected vertex because it has two ends there.

Changed in version 1.0: Returns a list in order of addition. In 0.6.5 this was the graph’s own set, with no defined order, although the documentation said list.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> g.add_edge(v1, v2)
Edge{[v1] -- [v2], cost=1.414}
>>> print(g.edges())
[Edge{[v1] -- [v2], cost=1.414}]

Vertex.edges() ne

Graph.average_degree()[source]

Average degree of the graph

Returns:

average degree

Return type:

float

Average degree is \(2 E / N\) where \(E\) is the total number of edges and \(N\) is the number of vertices, for an undirected or a directed graph. It is the mean of Vertex.degree, and every edge has two ends, so the degrees sum to \(2 E\).

Parallel edges and self-loops are each counted as one edge in \(E\); a self-loop contributes 2 to the degree sum.

Changed in version 1.0: For a DGraph this was \(E / N\), the mean out-degree (which equals the mean in-degree). It is now \(2 E / N\), the mean of the degree, which is twice the old value. Use g.ne / g.n for the previous number.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(name='v1')
>>> v2 = g.add_vertex(name='v2')
>>> v3 = g.add_vertex(name='v3')
>>> g.add_edge(v1, v2);
Edge{[v1] -- [v2], cost=None}
>>> g.add_edge(v2, v3);
Edge{[v2] -- [v3], cost=None}
>>> print(g.average_degree())
1.3333333333333333
Seealso:

degree() connectivity() Vertex.degree

Graph.iscyclic()[source]

Test if graph is cyclic

Returns:

true if the graph contains at least one cycle

Return type:

bool

For an undirected graph this is a simple count: a forest (acyclic) has exactly n - nc edges, one per component-connecting edge with no redundancy, so any excess indicates a cycle. This is O(1) given n(), ne() and nc(), which are already cached.

For a directed graph this runs Kahn’s algorithm: repeatedly remove vertices with no remaining incoming edges. If every vertex can eventually be removed, the graph is a DAG (acyclic); if some are never freed, they form a cycle. This is O(V+E), using vertices’ outgoing edges via Vertex.adjacent() the same way path_BFS() and friends do.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(name='v1')
>>> v2 = g.add_vertex(name='v2')
>>> v3 = g.add_vertex(name='v3')
>>> g.add_edge(v1, v2)
Edge{[v1] -- [v2], cost=None}
>>> g.add_edge(v2, v3)
Edge{[v2] -- [v3], cost=None}
>>> print(g.iscyclic())
False
>>> g.add_edge(v3, v1)
Edge{[v3] -- [v1], cost=None}
>>> print(g.iscyclic())
True

Note

A self-loop is a cycle of length one, so it makes either kind of graph cyclic. Two parallel edges between the same pair of vertices are a cycle in an undirected graph, but a repeated arrow in a directed graph is not.

Note

A matrix-based test also exists in theory – a digraph is acyclic iff its adjacency matrix is nilpotent (all eigenvalues zero) – but that needs an O(N^3) eigendecomposition plus a floating-point zero-tolerance judgement call, to answer a question Kahn’s algorithm answers exactly with integers in O(V+E). Not used here for that reason.

Seealso:

adjacency()

Graph.connectivity(vertices=None)[source]

Graph connectivity

Parameters:

vertices (iterable of Vertex subclass, optional) – vertices to report connectivity for, defaults to all vertices in the graph

Returns:

a list with the number of edges per vertex

Return type:

list

This is the Vertex.degree of each vertex: the number of edge ends at it, which is the number of edges connected to it except that a self-loop has two ends and so counts twice. For a directed graph it counts the edges entering the vertex as well as those leaving.

Changed in version 1.0: For a DGraph this counted only the edges leaving each vertex. Use [v.out_degree for v in g] for the previous values.

The average vertex connectivity is:

mean(g.connectivity())

and the minimum vertex connectivity is:

min(g.connectivity())

>>> from pgraph import UGraph
>>> import numpy as np
>>> g = UGraph()
>>> for i in range(5):
...     g.add_vertex(np.random.rand(2));
Vertex[#0, coord=(0.7852, 0.3324)]
Vertex[#1, coord=(0.6914, 0.1485)]
Vertex[#2, coord=(0.8769, 0.7103)]
Vertex[#3, coord=(0.09701, 0.4173)]
Vertex[#4, coord=(0.6605, 0.49)]
>>> for i, j in [(0, 1), (0, 2), (0, 3), (1, 2), (1, 3), (3, 4)]:
...     g.add_edge(g[i], g[j]);
Edge{[#0] -- [#1], cost=0.2064}
Edge{[#0] -- [#2], cost=0.3889}
Edge{[#0] -- [#3], cost=0.6934}
Edge{[#1] -- [#2], cost=0.5917}
Edge{[#1] -- [#3], cost=0.6523}
Edge{[#3] -- [#4], cost=0.5682}
>>> c = g.connectivity()
>>> print(c)
[3, 3, 2, 3, 1]

Note

This is the diagonal of degree(). Parallel edges are counted individually.

Graph.closest(coord)[source]

Vertex closest to point

Parameters:

coord (ndarray(n)) – coordinates of a point

Returns:

closest vertex and its distance, or (None, inf) if no vertex in the graph has a coordinate

Return type:

Vertex subclass or None, float

Returns the vertex closest to the given point. Distance is computed according to the graph’s metric. Vertices without a coordinate (coord is None) are skipped – they have no position to compare.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[10,10], name='v2')
>>> vertex, d = g.closest([1, 1])
>>> print(vertex, d)
[v1] 1.4142135623730951

Vertex.edges()[source]

Return a list of the edges for vertex

Returns:

the edges at this vertex

Return type:

list of Edge

For a directed graph these are the edges leaving this vertex. For an undirected graph they are the edges incident on it, whichever end it is. A self-loop in an undirected graph is listed twice, once for each end.

The list is a new one on every call, in the order the edges were connected, so changing it does not change the graph, and edges can be removed from the graph while iterating over it. Use Graph.remove_edge() to remove one.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> g.add_edge(v1, v2)
Edge{[v1] -- [v2], cost=1.414}
>>> print(v1.edges())
[Edge{[v1] -- [v2], cost=1.414}]
Seealso:

out_edges() in_edges() adjacent() incidences() edges_to() degree Graph.edges()

Vertex.adjacent()[source]

Vertices adjacent to this vertex

Returns:

the vertices at the far end of this vertex’s edges

Return type:

list of Vertex subclass

v.adjacent() is a list of the vertices that this vertex is joined to by an edge. “Adjacent” is the graph-theory term, and it is the relation that Graph.adjacency() tabulates: row i of the adjacency matrix is non-zero exactly at the columns of the vertices returned by g[i].adjacent().

Note

  • For a directed graph these are the vertices at the head of the edges leaving this vertex, the successors.

  • There is one entry per edge, so a vertex joined by k parallel edges appears k times. In an undirected graph a self-loop lists the vertex itself twice, once for each end.

  • neighbours and neighbors are aliases, the same method under the British and American spellings, and are not deprecated.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> v3 = g.add_vertex(coord=[2,2], name='v3')
>>> g.add_edge(v1, v2)
Edge{[v1] -- [v2], cost=1.414}
>>> g.add_edge(v1, v3)
Edge{[v1] -- [v3], cost=2.828}
>>> print(v1.adjacent())
[Vertex[v2, coord=(1, 1)], Vertex[v3, coord=(2, 2)]]
Seealso:

isadjacent() successors() predecessors() incidences() out_edges() edges() Graph.adjacency()

Vertex.incidences()[source]

Adjacent vertices paired with the edges that lead to them

Returns:

a (vertex, edge) pair for each edge leaving this vertex, in the order the edges were connected

Return type:

list of (Vertex subclass, Edge)

v.incidences() is adjacent() and out_edges() taken together: the first element of each pair is the vertex at the far end of the edge, the second is the edge itself, so its Edge.cost and Edge.data are at hand. It is equivalent to:

list(zip(v.adjacent(), v.out_edges()))

but is built in a single pass, which is what the path-planning methods want when they expand a vertex.

Note

  • In graph-theory terms adjacent() is a vertex’s adjacency list, out_edges() its incidence list, and this is the two joined.

  • For a directed graph the pairs are for the edges leaving this vertex. The ones entering it are in_edges(), and the vertices at their tails are predecessors().

  • There is one pair per edge, so parallel edges to the same vertex give repeated vertices with different edges, and an undirected self-loop gives the pair twice, once for each end.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> v3 = g.add_vertex(coord=[2,2], name='v3')
>>> g.add_edge(v1, v2, cost=1.5)
Edge{[v1] -- [v2], cost=1.5}
>>> g.add_edge(v1, v3, cost=2.5)
Edge{[v1] -- [v3], cost=2.5}
>>> for vertex, edge in v1.incidences():
...     print(vertex.name, edge.cost)
v2 1.5
v3 2.5

property Vertex.degree: int

Degree of vertex

Returns:

degree of the vertex

Return type:

int

The number of edge ends at this vertex: the edges leaving it plus the edges entering it, so a self-loop counts twice. The degrees of all the vertices of a graph sum to twice its number of edges.

For an undirected graph this is the number of incident edges. For a directed graph it is in_degree + out_degree.

Changed in version 1.0: For a DGraph this used to count only the edges leaving the vertex. It is now the graph-theory degree, in plus out. Use out_degree for the previous value.

>>> from pgraph import DGraph
>>> g = DGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> v3 = g.add_vertex(coord=[2,2], name='v3')
>>> g.add_edge(v1, v2)
Edge{[v1] -> [v2], cost=1.414}
>>> g.add_edge(v1, v3)
Edge{[v1] -> [v3], cost=2.828}
>>> g.add_edge(v3, v1)
Edge{[v3] -> [v1], cost=2.828}
>>> print(v1.degree, v1.in_degree, v1.out_degree)
3 1 2

For graphs with parallel edges or loops

Every edge is counted, so k parallel edges to the same vertex add k. A self-loop adds 2, for both kinds of graph: it has two ends.
