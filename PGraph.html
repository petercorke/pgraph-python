Create graph from adjacency matrix

Parameters:

  • A (ndarray(N,N)) – adjacency matrix

  • coords (ndarray(N,M), optional) – coordinates of vertices, defaults to None

  • names (list(N) of str, optional) – names of vertices, defaults to None

  • kwargs (Any) – optional arguments passed to the graph constructor, for example vertex_class or edge_class

Raises:

  • ValueError – A is not square, or the length of names or the number of rows of coords does not match A

  • TypeError – vertex_class or edge_class is not a suitable class, see BaseGraph.__init__()

Returns:

graph

Return type:

UGraph or DGraph

Create a directed or undirected graph where non-zero elements A[i,j] correspond to edges from vertex i to vertex j.

A non-zero diagonal element A[i,i] is a self-loop on vertex i, for both kinds of graph.

Warning

For undirected graph A should be symmetric but this is not checked. Only the upper triangular part, including the diagonal, is used. Elements are costs, not edge counts: a non-zero element is a single edge with that element as its cost, so parallel edges cannot be created this way.

>>> from pgraph import UGraph
>>> import numpy as np
>>> A = np.array([[0, 1, 0], [1, 0, 1], [0, 1, 0]])
>>> g = UGraph.Adjacency(A)
>>> print(g)
UGraph: 3 vertices, 2 edges, 1 component

Add an edge to the graph (base class method)

Parameters:

  • v2 (BaseVertex subclass or str, optional) – second vertex (end if a directed graph), must be omitted if v1 is an edge

  • kwargs (Any) – optional arguments to pass to BaseVertex.connect, not allowed if v1 is an edge

Raises:

  • TypeError – v1 or v2 is of the wrong type, or v2, cost or data is given along with an edge

  • ValueError – the edge has no vertices, or the vertices do not belong to this graph

Returns:

edge

Return type:

Edge

  • g.add_edge(v1, v2) creates an edge between a vertex pair and adds it to the graph.

  • g.add_edge(e) takes an edge, or an instance of an Edge subclass, that was constructed with its two vertices and adds it to the graph, just as g.add_vertex(v) takes an existing vertex.

This is a graph centric way of creating an edge. The alternative is the connect method of a vertex.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> v3 = g.add_vertex(coord=[2,2], name='v3')
>>> e = g.add_edge(v1, v2)
>>> print(e)
Edge{[v1] -- [v2], cost=1.414}
>>> e2 = g.add_edge('v2', 'v3', cost=99)
>>> print(e2)
Edge{[v2] -- [v3], cost=99}

Adding an instance of a user-defined Edge subclass:

>>> from pgraph import UGraph, Edge
>>> class MyEdge(Edge):
...     pass
>>> g = UGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> e = g.add_edge(MyEdge(v1, v2, data="a road"))
>>> print(type(e).__name__, e.data)
MyEdge a road

Note

To supply an edge that does not yet have vertices use g.add_edge(v1, v2, edge=e) or e.connect(v1, v2).

add_vertex(coord=None, name=None)[source]

Add a vertex to the graph

Parameters:

  • coord (array-like or BaseVertex subclass, optional) – coordinate for an embedded graph, or an existing vertex of this graph’s own kind (UVertex for UGraph, DVertex for DGraph) to add as-is, defaults to None

  • name (str, optional) – name of vertex, defaults to “#i”

Raises:

  • TypeError – coord is a BaseVertex that is not an instance of this graph’s vertex_class

  • ValueError – the name is already used by another vertex in the graph, or coord is a vertex that already belongs to a graph

  • ValueError – the graph was constructed with dim, and coord is given but its length doesn’t match

Returns:

the added vertex

Return type:

BaseVertex subclass

  • g.add_vertex() creates a new vertex with optional coord and name.

  • g.add_vertex(v) takes an instance of this graph’s vertex_class (by default any UVertex for a UGraph, any DVertex for a DGraph) and adds it to the graph.

If the vertex has no name and name is None give it a default name #N where N is the number of vertices, or the next integer above it that is not already used by a name in the graph.

Names are unique within a graph, since they are how g[name] finds a vertex, and a vertex belongs to one graph at a time.

Changed in version 1.0: Adding a vertex whose name is already used raises ValueError. It used to replace the earlier vertex in the name table, leaving it in the graph but unreachable by name. A default name could also clash with an existing one after a vertex had been removed.

The vertex is placed into a dictionary with a key equal to its name.

This single implementation, shared by UGraph and DGraph, is parameterized by the graph’s vertex_class rather than duplicated per subclass – see Object lifecycle and graph-membership policy for why that matters.

>>> from pgraph import UGraph, UVertex
>>> g = UGraph()
>>> v1 = g.add_vertex(coord=[0,0])
>>> print(v1.name)
#0
>>> v2 = g.add_vertex(UVertex(coord=[1,1], name='v2'))
>>> print(v2.name)
v2

If the graph was constructed with a required dim (see BaseGraph.__init__()), every embedded vertex must have a coordinate of exactly that length – adding one of the wrong length raises ValueError:

>>> from pgraph import UGraph
>>> g = UGraph(dim=6)
>>> v1 = g.add_vertex(coord=[0, 0, 0, 0, 0, 0], name='pose1')
>>> print(v1)

adjacency()[source]

Adjacency matrix of graph

Returns:

adjacency matrix

Return type:

ndarray(N,N)

The elements of the adjacency matrix [i,j] are 1 if vertex i is connected to vertex j, else 0.

>>> from pgraph import UGraph
>>> import numpy as np
>>> g = UGraph()
>>> for i in range(5):
...     g.add_vertex(np.random.rand(2))
UVertex[#0, coord=(0.2516, 0.4813)]
UVertex[#1, coord=(0.01787, 0.8396)]
UVertex[#2, coord=(0.04833, 0.9021)]
UVertex[#3, coord=(0.2012, 0.7276)]
UVertex[#4, coord=(0.9818, 0.6847)]
>>> for i, j in [(0, 1), (0, 2), (0, 3), (1, 2), (1, 3), (3, 4)]:
...     g.add_edge(g[i], g[j])
Edge{[#0] -- [#1], cost=0.4278}
Edge{[#0] -- [#2], cost=0.4674}
Edge{[#0] -- [#3], cost=0.2514}
Edge{[#1] -- [#2], cost=0.06961}
Edge{[#1] -- [#3], cost=0.2148}
Edge{[#3] -- [#4], cost=0.7818}
>>> A = g.adjacency()
>>> print(A)
[[0. 1. 1. 1. 0.]
 [1. 0. 1. 1. 0.]
 [1. 1. 0. 0. 0.]
 [1. 1. 0. 0. 1.]
 [0. 0. 0. 1. 0.]]

Note

  • vertices are numbered in their order of creation. A vertex index can be resolved to a vertex reference by graph[i].

  • for an undirected graph the matrix is symmetric

  • Eigenvalues of A are real and are known as the spectrum of the graph.

  • The element A[i,j] is the number of walks of length one edge from vertex i to vertex j, which is the number of edges between them (zero or one for a simple graph).

  • If Ak = A ** k the element Ak[i,j] is the number of walks of length k from vertex i to vertex j.

For graphs with parallel edges or loops

The matrix holds edge counts, so k parallel edges from i to j give A[i,j] = k and Ak = A ** k still counts walks correctly. A self-loop adds to the diagonal: 2 for a UGraph (consistent with degree()) and 1 for a DGraph. In every case each row of A sums to the degree of that vertex.

average_degree()[source]

Average degree of the graph

Returns:

average degree

Return type:

float

Average degree is \(2 E / N\) where \(E\) is the total number of edges and \(N\) is the number of vertices, for an undirected or a directed graph. It is the mean of BaseVertex.degree, and every edge has two ends, so the degrees sum to \(2 E\).

Parallel edges and self-loops are each counted as one edge in \(E\); a self-loop contributes 2 to the degree sum.

Changed in version 1.0: For a DGraph this was \(E / N\), the mean out-degree (which equals the mean in-degree). It is now \(2 E / N\), the mean of the degree, which is twice the old value. Use g.ne / g.n for the previous number.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(name='v1')
>>> v2 = g.add_vertex(name='v2')
>>> v3 = g.add_vertex(name='v3')
>>> g.add_edge(v1, v2)
Edge{[v1] -- [v2], cost=None}
>>> g.add_edge(v2, v3)
Edge{[v2] -- [v3], cost=None}
>>> print(g.average_degree())
1.3333333333333333

connectivity(vertices=None)[source]

Graph connectivity

Parameters:

vertices (iterable of BaseVertex subclass, optional) – vertices to report connectivity for, defaults to all vertices in the graph

Returns:

a list with the number of edges per vertex

Return type:

list

This is the BaseVertex.degree of each vertex: the number of edge ends at it, which is the number of edges connected to it except that a self-loop has two ends and so counts twice. For a directed graph it counts the edges entering the vertex as well as those leaving.

Changed in version 1.0: For a DGraph this counted only the edges leaving each vertex. Use [v.out_degree for v in g] for the previous values.

The average vertex connectivity is:

mean(g.connectivity())

and the minimum vertex connectivity is:

min(g.connectivity())

degree()[source]

Degree matrix of graph

Returns:

degree matrix

Return type:

ndarray(N,N)

This is a diagonal matrix where element [i,i] is the BaseVertex.degree of vertex i: the number of edge ends at it, so a self-loop counts twice. For a directed graph that is the edges entering plus the edges leaving.

Changed in version 1.0: For a DGraph this was the out-degree matrix, counting only the edges leaving each vertex. It is now the total, in plus out. The old matrix is np.diag([v.out_degree for v in g]), which is what laplacian() uses.

dotfile(filename=None, direction=None)[source]

Export graph as a GraphViz dot file

Parameters:

  • filename (str, path-like or file object, optional) – filename to save graph to, defaults to None

  • direction (str, optional) – layout direction, eg. "LR", defaults to None

Return type:

None

g.dotfile() creates the specified file which contains the GraphViz code to represent the embedded graph. By default output is to the console.

This is export() with format="dot" and edge costs left unlabelled, as it has always been. Use export() for other formats or for edge labels.

Note

  • The graph is undirected if it is a subclass of UGraph

  • The graph is directed if it is a subclass of DGraph

The graphviz formatters dot and neato can be used to render the graph in various formats including PDF, PNG, JPG, GIF, SVG, etc. The formmatters are similar, but dot is better suited for directed graphs while neato is better suited for undirected graphs.

Note

If filename is a file object then the file will not be closed after the GraphViz model is written.

>>> g = UGraph()

>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> g.add_edge(v1, v2)

>>> g.dotfile()
graph {
  "v1" [pos="0,0!"]
  "v2" [pos="1,1!"]
  "v1" -- "v2"
}

Note

  • Output is reproducible: vertices are written in creation order and edges in the order of their vertices, not in set order.

  • A file object passed as filename is written but not closed. A path is opened, and closed even if writing fails.

  • Names are escaped for each format, and Mermaid, GraphML and ELK use generated ids so any vertex name is valid.

For graphs with parallel edges or loops

Every edge is written, each with its own cost, so parallel edges give repeated lines (DOT, Mermaid) or distinct id elements (GraphML, ELK). A self-loop is written once, as an edge from a vertex to itself.

iscyclic()[source]

Test if graph is cyclic

Returns:

true if the graph contains at least one cycle

Return type:

bool

For an undirected graph this is a simple count: a forest (acyclic) has exactly n - nc edges, one per component-connecting edge with no redundancy, so any excess indicates a cycle. This is O(1) given n(), ne() and nc(), which are already cached.

For a directed graph this runs Kahn’s algorithm: repeatedly remove vertices with no remaining incoming edges. If every vertex can eventually be removed, the graph is a DAG (acyclic); if some are never freed, they form a cycle. This is O(V+E), using vertices’ outgoing edges via BaseVertex.adjacent() the same way path_BFS() and friends do.

Note

A self-loop is a cycle of length one, so it makes either kind of graph cyclic. Two parallel edges between the same pair of vertices are a cycle in an undirected graph, but a repeated arrow in a directed graph is not.

Note

A matrix-based test also exists in theory – a digraph is acyclic iff its adjacency matrix is nilpotent (all eigenvalues zero) – but that needs an O(N^3) eigendecomposition plus a floating-point zero-tolerance judgement call, to answer a question Kahn’s algorithm answers exactly with integers in O(V+E). Not used here for that reason.

validate()[source]

Check that the graph’s records agree with each other

Returns:

a description of each inconsistency found, empty if the graph is consistent

Return type:

list of str

A graph keeps the same facts in several places: its set of edges, each vertex’s list of outgoing edges (and, for a directed graph, of incoming ones), each edge’s two vertices, each vertex’s pointer back to its graph, and the table of vertex names. The library keeps them in step, so a graph built and edited through the public methods is always valid. This is a check for tests, for debugging, and for code that reaches into the internals.

It does not change the graph, and takes time proportional to the number of vertices plus edges. It reports every inconsistency, not only the first.

The checks are:

  • the vertex list holds only vertices, once each, and the edge set holds only edges

  • every edge in the graph has two vertices, both in this graph, and is an instance of edge_class

  • every vertex points back at this graph, is an instance of vertex_class, is in the name table under its own name, and has a coordinate of the required length if dim was given

  • every entry of the name table is a vertex of this graph and is filed under its own name

  • each edge is in the right vertex lists, the right number of times: both ends for an undirected edge (twice at one vertex for a self-loop), the source’s outgoing and the target’s incoming list for a directed edge

  • no vertex list holds an edge that is not in the graph

property degree: int

Degree of vertex

Returns:

degree of the vertex

Return type:

int

The number of edge ends at this vertex: the edges leaving it plus the edges entering it, so a self-loop counts twice. The degrees of all the vertices of a graph sum to twice its number of edges.

For an undirected graph this is the number of incident edges. For a directed graph it is in_degree + out_degree.

Changed in version 1.0: For a DGraph this used to count only the edges leaving the vertex. It is now the graph-theory degree, in plus out. Use out_degree for the previous value.

>>> from pgraph import DGraph
>>> g = DGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> v3 = g.add_vertex(coord=[2,2], name='v3')
>>> g.add_edge(v1, v2)
Edge{[v1] -> [v2], cost=1.414}
>>> g.add_edge(v1, v3)
Edge{[v1] -> [v3], cost=2.828}
>>> g.add_edge(v3, v1)
Edge{[v3] -> [v1], cost=2.828}
>>> print(v1.degree, v1.in_degree, v1.out_degree)
3 1 2

For graphs with parallel edges or loops

Every edge is counted, so k parallel edges to the same vertex add k. A self-loop adds 2, for both kinds of graph: it has two ends.

incidences()[source]

Adjacent vertices paired with the edges that lead to them

Returns:

a (vertex, edge) pair for each edge leaving this vertex, in the order the edges were connected

Return type:

list of (BaseVertex subclass, Edge)

v.incidences() is adjacent() and out_edges() taken together: the first element of each pair is the vertex at the far end of the edge, the second is the edge itself, so its Edge.cost and Edge.data are at hand. It is equivalent to:

list(zip(v.adjacent(), v.out_edges()))

but is built in a single pass, which is what the path-planning methods want when they expand a vertex.

Note

  • In graph-theory terms adjacent() is a vertex’s adjacency list, out_edges() its incidence list, and this is the two joined.

  • For a directed graph the pairs are for the edges leaving this vertex. The ones entering it are in_edges(), and the vertices at their tails are predecessors().

  • There is one pair per edge, so parallel edges to the same vertex give repeated vertices with different edges, and an undirected self-loop gives the pair twice, once for each end.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> v3 = g.add_vertex(coord=[2,2], name='v3')
>>> g.add_edge(v1, v2, cost=1.5)
Edge{[v1] -- [v2], cost=1.5}
>>> g.add_edge(v1, v3, cost=2.5)
Edge{[v1] -- [v3], cost=2.5}
>>> for vertex, edge in v1.incidences():
...     print(vertex.name, edge.cost)
v2 1.5
v3 2.5

Edge class

Is used to represent directed directed and undirected edges.

Each edge has: - cost cost of traversing this edge, required for planning methods - data reference to arbitrary data associated with the edge - v1 first vertex, start vertex for a directed edge (read-only) - v2 second vertex, end vertex for a directed edge (read-only)
