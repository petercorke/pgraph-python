Exporting a graph

Graphs can be exported to a number of different formats, including dot (used by GraphViz) mermaid (a JavaScript-based graph visualization tool that can be used in MarkDown documents), GraphML (an XML-based format for representing graphs), ELK (a graph layout engine), as well as various image formats (e.g., PNG, SVG, PDF).

See Visualization for rendering the graph using Matplotlib itself rather than exporting it.

export

Convert and save the graph in a graph export or image format

dotfile

Export graph as a GraphViz dot file

BaseGraph.export(filename=None, format=None, **options)[source]

Convert and save the graph in a graph export or image format

Parameters:

  • filename (str, path-like or file object, optional) – destination path or open file, defaults to None

  • format (str, optional) – "dot", "mermaid", "graphml", "elk" or an image format "svg", "pdf", "png" …, inferred from the extension of filename if not given

  • options (Any) – format specific options, see below

Raises:

  • ValueError – the format is unknown or cannot be inferred, or an image format is requested without a filename

  • TypeError – an option is not valid for the format

  • RuntimeError – an image format is requested and GraphViz is not installed, or fails

Returns:

the text if filename is None, otherwise None

str or None

The text formats need nothing beyond the standard library. The image formats run the GraphViz dot or neato executable.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> g.add_edge(v1, v2, cost=2)
Edge{[v1] -- [v2], cost=2}
>>> print(g.export(format="mermaid", direction="LR"))
flowchart LR
    n0["v1"]
    n1["v2"]
    n0 ---|"2"| n1

Note

  • Output is reproducible: vertices are written in creation order and edges in the order of their vertices, not in set order.

  • A file object passed as filename is written but not closed. A path is opened, and closed even if writing fails.

  • Names are escaped for each format, and Mermaid, GraphML and ELK use generated ids so any vertex name is valid.

For graphs with parallel edges or loops

Every edge is written, each with its own cost, so parallel edges give repeated lines (DOT, Mermaid) or distinct id elements (GraphML, ELK). A self-loop is written once, as an edge from a vertex to itself.

BaseGraph.dotfile(filename=None, direction=None)[source]

Export graph as a GraphViz dot file

Parameters:

  • filename (str, path-like or file object, optional) – filename to save graph to, defaults to None

  • direction (str, optional) – layout direction, eg. "LR", defaults to None

Return type:

None

g.dotfile() creates the specified file which contains the GraphViz code to represent the embedded graph. By default output is to the console.

This is export() with format="dot" and edge costs left unlabelled, as it has always been. Use export() for other formats or for edge labels.

Note

  • The graph is undirected if it is a subclass of UGraph

  • The graph is directed if it is a subclass of DGraph

Note

The graphviz formatters dot and neato can be used to render the graph in various formats including PDF, PNG, JPG, GIF, SVG, etc. The formmatters are similar, but dot is better suited for directed graphs while neato is better suited for undirected graphs.

>>> from pgraph import UGraph
>>> g = UGraph()
>>> v1 = g.add_vertex(coord=[0,0], name='v1')
>>> v2 = g.add_vertex(coord=[1,1], name='v2')
>>> g.add_edge(v1, v2)
Edge{[v1] -- [v2], cost=1.414}
>>> g.dotfile()
graph {
  "v1" [pos="0,0!"]
  "v2" [pos="1,1!"]
  "v1" -- "v2"
}

Note

Edge costs are not included in the output. Use export() with costs=True to include them.

Note

If filename is a file object then the file will not be closed after the GraphViz model is written. Safe for use with sys.stdout or sys.stderr.
